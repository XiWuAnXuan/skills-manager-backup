# 对接经验知识库（常见问题与解决方案）

> 本文件沉淀 PMS 门锁对接实战中的技术要点、踩坑记录与解决方案。按类别组织，可当作速查表使用。

## 1. 编译环节的坑

### 1.1 build.bat 中文乱码 → 脚本被拆成乱码命令执行
**现象**：双击 build.bat 报一堆 `'Win7' 不是内部或外部命令`、`'洪厤缃?'`、`'鍙戝崱'` 等乱码错误，编译根本没跑。
**原因**：cmd 按系统代码页（GBK）解析 .bat，脚本里 UTF-8 编码的中文被逐字节当成命令执行。
**解决**：**.bat 脚本永远只写 ASCII**——零中文、零 chcp、无 BOM。中文只允许出现在 .cs 源码里（UTF-8 BOM + `/codepage:65001` 双保险）。

### 1.2 if 括号块内 echo 含 `)` → else 分支误触发
**现象**：编译其实成功了（`[OK] generated`），但脚本又打印 `[FAIL]`。
**原因**：`if ( ... ) else ( ... )` 括号块内的 echo 文字含 `)`（如 `(from SDK folder)`），cmd 把 `)` 误认为块结束。
**解决**：用 `if errorlevel 1 goto :fail` + `goto :end` 的 goto 结构，**彻底不用 if-else 大括号块**；echo 文本不含括号字符。

### 1.3 32 位 DLL 的编译目标
**现象**：运行时 `BadImageFormatException` 或找不到 DLL。
**原因**：锁厂 DLL 是 32 位，程序必须是 x86。
**解决**：C# 编译加 `/platform:x86`（Framework 自带 csc 即可，无需安装 SDK）。

### 1.4 缺 using / 编译报 CS0246
**现象**：`List`/`Dictionary` 找不到（CS0246）。
**原因**：批量队列等功能用了 `System.Collections.Generic` 但文件头没 using。
**解决**：逐个文件核对 using；注意用正则检查时排除注释误报（如 `IsLockNoFormat` 里的 `Format` 字符、`[STAThread]` 里的 `Thread`）。

## 2. 运行时/界面层的坑

### 2.1 WinForms 跨线程访问控件异常
**现象**：后台线程操作控件抛 `InvalidOperationException`（跨线程访问）。
**解决**：**在 UI 线程预取控件值**（点按钮时先读入局部变量再传给后台线程）；UI 更新用 `BeginInvoke`。

### 2.2 串口刚打开立即读卡 → 误报"无卡"
**现象**：打开串口后同一秒点读卡，返回无卡；几秒后重试成功。
**原因**：发卡机刚上电/初始化未就绪。
**解决**：`OpenPort` 成功后 `Thread.Sleep(400)` 再操作。

### 2.3 新卡(返回码7)被误报"读卡失败"
**现象**：读到空白新卡（注销后的卡）显示"读卡失败：新卡"。
**原因**：代码把 7 归入错误分支。**7=新卡是正常状态**（卡存在但没数据）。
**解决**：
- 读卡 r==7 → 提示"这是一张新卡（空白卡），尚未写入任何房间信息"（Info 图标）。
- 注销 r==7 → 提示"该卡本来就是新卡，无需注销"。

### 2.4 DateTimePicker 难用 / 弹出后还要再点箭头
**现象**：失效时间选择控件难操作。
**解决**：用 **MaskedTextBox（掩码 `0000-00-00 00:00` + 大号字体）** 支持直接打字，右侧【📅】按钮弹出**自定义日历弹窗**（MonthCalendar 选日期 + 时/分 NumericUpDown + 确定/取消），一次操作到位。
**坑**：`DateTimePicker.DropDown` 是**事件**不是方法，`DropDown()` 调用会报 CS0079，用 `Visible+BringToFront+Focus` 代替。

### 2.5 界面被要求去掉日志框/状态栏
**注意**：PMS 认结果的 `{日期}/{UID}.txt` 记录文件**不能删不能合并**；人工日志另建统一文件（如 `开锁日志.log`，一行一条追加，`lock` 保证线程安全）。

### 2.6 SDK 用相对路径读配置/授权文件 → 必须切工作目录

**现象**：官方 Demo（双击运行）一切正常，自己写的程序被 PMS 拉起后报
「通讯错误」「授权错误」等，参数明明一样。

**原因**：锁厂 DLL 内部是用**相对路径**去读同目录的配置文件（如 `LcSDK.ini`）和
授权凭证（如 `sdkid.txt`）的，走的是**进程当前工作目录（CWD）**，
`SetDllDirectory` 只管 DLL 搜索路径，**管不到这类 fopen**。

- 双击 Demo 时：CWD = Demo 所在目录 → 读得到 ✅
- PMS `spawn` 拉起时：CWD = PMS 安装目录 → **读不到** ❌

**解决**：加载 DLL 后立即把 CWD 切到 SDK 目录：

```csharp
SetDllDirectory(sdkDir);
Directory.SetCurrentDirectory(sdkDir);   // 关键，不能省
```

同时在自检模式里把「工作目录 / 授权文件 / 配置文件」三行打印出来，现场一眼就能定位。

### 2.7 授权凭证是「每个目录一份」，状态各不相同

同一份 DLL 放在不同目录、配不同的 `sdkid.txt`，授权状态就不同。
实测同一项目三处 `sdkid.txt` 内容完全不同（72 字节=已授权 / 12 字节=`00FF00FF` 空白 / 30 字节=另一套 ID）。

**关键推论**：**「Demo 能读卡」不等于「你的运行目录也已授权」** ——
它只说明 Demo 所在目录那份授权档是好的。
换目录部署后若报 128/5/4 这类码，先比对两份 `sdkid.txt` 的字节数与内容。

**排查顺序**：① 切 CWD → ② 用 Demo 目录的 `sdkid.txt` 覆盖试 → ③ 跑 `SDKAuth.exe` 正规授权
→ ④ 同目录跑官方 `RWCardDemo.exe` 交叉验证，隔离「本程序问题」还是「环境问题」。

### 2.8 读卡前卡片必须先被门锁软件写过一次客人卡

锁厂文档明确：**卡片必须经门锁系统写过一次客人卡**（写入客人卡标识）才能被接口读出，
否则读卡直接失败。空白卡直接读是读不到的。

另外文档还规定：**开门卡在 PMS 发行，其他管理类卡片（总卡/栋卡/层卡/时钟卡）
必须在门锁软件里发行**，且「禁止多个门锁软件在不同卡片之间串发」。
某张卡若经过门锁软件自身的注销/回收，需重新发行一次客人卡，否则接口读写会失败。

## 3. 并发与重复开卡

### 3.1 多进程抢串口 → 单实例 Mutex + 命名管道（方案B）
**背景**：PMS 每次开卡启动新进程，重复开卡 = 多进程并发抢串口。
**方案**：
1. 首实例创建命名 `Mutex(true, MutexName)` 持有；后续实例 `Mutex.WaitOne(0)` 失败 → 说明已有实例。
2. 后续实例把参数通过**命名管道**（`NamedPipeClientStream` → `PipeServer.Send(args[0])`）转发给首实例后退出。
3. 首实例（`NamedPipeServerStream` 异步监听）收到参数 → `ApplyNewTask()`：`Show+Activate+BringToFront` + 解析新房号替换队列 + 刷新界面。
4. 进程内 `lock (SdkLock)` 串行化所有 SDK 调用。
5. 全部房间完成 → `Close()` 释放 Mutex/串口。

### 3.2 Windows 前台锁定：后台实例弹不到前台
**现象**：方案B 生效（信息已更新）但窗口只在任务栏闪图标。
**原因**：系统只允许"前台进程/刚有用户输入"的进程抢前台，后台 `Activate/BringToFront` 无效。
**解决（可选，先确认需求）**：`RestoreToForeground()` 三层保障：
1. 最小化恢复：`WindowState=Normal` + `ShowWindow(SW_RESTORE)`；
2. `AttachThreadInput(当前线程, 前台线程, true)` → `SetForegroundWindow` → 摘除；
3. 兜底：`keybd_event(VK_MENU)` 模拟 Alt 获得"用户输入"资格 → `SetForegroundWindow`。
**⚠️ 经验教训**：用户可能不接受强制抢前台（实测要求回退过），**先问再实现**。

### 4.2 Temic/EM 门锁 LCRFRW_SDK.dll

| 132 | 授权卡错误 | 接口程序不能处理授权卡 → 换开门卡 |
| 133 | 系统编号错误 | 输入的系统编号与卡中不一致 |
| 134 | 读写器授权错误 | 读写器授权与卡中系统编号不一致 |
| 135 | 接口授权到期 | 需重新用授权工具授权 |
| 256 | 系统错误 | 内部错误 |

> ⚠ **重要勘误（2026-09 实测）**：早期版本误把 `5` 记作「授权错误」、把 `7` 记作「新卡」，
> 这两个都是从别的锁厂表里串过来的，**对本 SDK 不成立**：
> 本 SDK 的 `5` 是**串口参数错**，`7` 根本未定义，**无卡是 `16`**。
> 现场若按错表排查，会把「没放卡」误判成「授权过期」，白白折腾一圈。
> 教训：**错误码表必须从该锁厂自己的接口文档里抄**，不要跨厂商套用。

**参数取值范围（同样来自该文档，越界会被直接拒绝）**

| 参数 | 取值范围 |
|---|---|
| `xh` 发卡序号 | **0~62**（当前小时内第几次写卡）。超过 62 需把 `fksj` 小时 +1 且序号重置为 0 |
| `sjlength` 时间长度 | 小时 1~63 / 天 1~63 / **月 1~15** / **年 1~3** |
| `sjdw` 时间单位 | 0=小时 1=天 2=月 3=年，其它按天 |
| `tfzd` 退房钟点 | 11~18（钟点房不受此限，写 11~18 之间任意值即可） |
| `gs` | 1=取消在用客人卡挂失，0=不取消不挂失 |
| `fs` | 0=不允许开反锁，1=允许 |

> ⚠ **「小时」单位的上限会咬人（实测踩过）**：`sjlength` 按「小时」计时时上限只有 **63**，即 2.6 天。
> 对接程序若统一用「小时」表达有效期，一张住 30 天的订单会算出 720 小时 →
> 被上限压成 63 → **卡 2.6 天后失效，客人剩 27 天打不开门**。
> 这种故障开卡时一切正常（返回 0），要到第三天客人才投诉，**极难回溯**。
>
> 正确做法：自动换算时按实际时长**自动挑单位** ——
> ≤63 小时用小时；≤63 天用天；≤15 月用月；更长用年。
> 并在开卡成功的提示里把实际生效的单位打出来（「有效时长：3 天」），方便现场核对。
>
> 同理注意：`月` 上限 15、`年` 上限 3，都别硬套一个大数字。

**退房回收卡片的官方写法**（文档原文）：

```
BH=实际门锁编号,  fksj=00000000,  xh=0,  sjdw=0,  sjlength=1,  gs=0
```

别自己发明「写一个过期时间 + 挂失位置 1」的做法 —— 按上面这组参数调 `tem_writedoorcard13_sdk` 即可。

### 4.3 串口号是 0 基索引（高频踩坑）

**现象**：官方 `TEST.EXE` 选某个 COM 口返回 0、读卡正常，但自己写的程序 / 原厂 exe
同样选那个口却报「通讯错误 / 通讯底层中断」。

**原因**：厂商 Demo 里写的是 `mif_selecom(ComboBox1.itemindex, baud)`，
而下拉列表内容是 `COM1..COM16` —— 传进去的是**下拉索引（0 基）**，不是 COM 号。
所以 **COM11 必须传 10**。

**正确做法**：配置项让人填人读的 COM 号，代码内部统一 `-1`，并在注释里写死这条规则。
现场排障时若怀疑偏移，把配置值 ±1 各试一次即可定位。

**验证硬件链路是否通**：先用厂商官方 Demo（如 `TEST.EXE`）测通，再比对自己程序的传参 ——
官方 Demo 能通而自己不通，九成是参数映射问题，不是硬件问题。

## 5. 房号/锁编号格式速查

| 场景 | 格式 | 示例 |
|---|---|---|
| PMS 下发房门号 | 4位数字 | `8201` |
| 锁编号（汉庭类，卡内 R 字段） | `R楼-层-房-门` | `R1-2-1-0` |
| 锁编号（Temic 类） | **固定 10 字符，无规律** | `Abcd0001` |
| 卡数据（汉庭类） | `T0\|R...\|DyyMMddHHmm\|OyyMMddHHmm\|L0` | `T0\|R1-2-1-0\|D2608061550\|O2608071400\|L0` |
| 时间（汉庭类卡内） | `yyMMddHHmm` | `2608071400` |
| 时间（Temic 类写卡） | `YYMMDDHH` | `26091014` |
| 时间（PMS 下发） | `yyyy-MM-dd HH:mm:ss` | `2026-08-07 12:00:00` |

**8xxx 房号 → 锁编号规则（仅适用于规则化编号的锁厂）**：`R1-{房号第2位}-{房号后两位去前导零}-0`。
例：8201→R1-2-1-0、8210→R1-2-10-0、8523→R1-5-23-0。

**Temic 类不适用上述规则** —— 门锁编号由门锁软件分配、毫无规律，
必须用锁厂工具 `GetLockID.exe` 从门锁软件导出对应表（`LockID.ini`）。

### 5.1 lock_room.txt 的等号方向（易搞反）

| 文件 | 方向 | 来源 |
|---|---|---|
| `lock_room.txt` | **门锁编号 = 房号** | 对接程序使用 |
| `LockID.ini` | **房号 = 门锁编号** | 锁厂 `GetLockID.exe` 生成 |

两者方向相反。推荐做法：程序读取时若发现只有 `LockID.ini`，自动反转生成 `lock_room.txt`，
省掉手工转换这一环（注意跳过 `LockID.ini` 末行的 `LockAP=X`，它不是房间映射）。

## 6. 需求边界与经验教训（重要）

- **不要擅自做结构性大改**：用户对"全屏独占/键盘锁定/单实例管道/日志隐藏"等未经明确要求的改动可能不满意并要求回退。**每次大改先确认，改动范围最小化**。
- **逆向"看懂"≠"改源码"**：商业编译型软件（如原 Delphi exe）只能逆向分析，无法还原成可编译源码；需要新功能时**重写对接程序**（走协议），不要试图改原 exe。
- **手动模式问题**：用户可能要求去掉"手动模式"（无参数启动直接提示退出），因为正常业务全靠 PMS 驱动；但 PMS 的**读卡/注销指令**（`room_no="读卡"` 或 `action=ReadCard/HotelCheckOut`）仍需打开操作界面，否则 PMS 对应功能失效。
- **多房间批量**：PMS 批量入住走 `Door_lock_call_initiate`，多房间数组逐个下发；对接程序用**队列**：开卡成功自动切换下一间（界面显示"第 X/N 间"），全部完成自动退出。
- **lockmodel（锁型号）**：PMS 后台配置后随指令下发，原版 exe 靠它选择同目录下对应锁厂接口目录；简化版对接程序可固定调用一个锁厂 DLL，日志显示后台 lockmodel 值便于核对。
- **界面显示房间号**：PMS 下发可能是房门号(8201)也可能是锁编号(R1-2-1-0)；显示用"锁编号反查房号"保证一致性；显示文字如"正在开：8201房间"。
