# 对接经验知识库（常见问题与解决方案）

> 本文件沉淀 PMS 门锁对接实战中的技术要点、踩坑记录与解决方案。按类别组织，可当作速查表使用。

## 1. 编译环节的坑

### 1.1 build.bat 中文乱码 → 脚本被拆成乱码命令执行
**现象**：双击 build.bat 报一堆 `'Win7' 不是内部或外部命令`、`'洪厤缃?'`、`'鍙戝崱'` 等乱码错误，编译根本没跑。
**原因**：cmd 按系统代码页（GBK）解析 .bat，脚本里 UTF-8 编码的中文被逐字节当成命令执行。
**解决**：**.bat 脚本永远只写 ASCII**——零中文、零 chcp、无 BOM。中文只允许出现在 .cs 源码里（UTF-8 BOM + `/codepage:65001` 双保险）。

### 1.2 if 括号块内 echo 含 `)` → else 分支误触发
**现象**：编译其实成功了（`[OK] generated`），但脚本又打印 `[FAIL]`。
**原因**：`if ( ... ) else ( ... )` 括号块内的 echo 文字含 `)`（如 `(from SDK folder)`），cmd 把 `)` 误认为块结束。
**解决**：用 `if errorlevel 1 goto :fail` + `goto :end` 的 goto 结构，**彻底不用 if-else 大括号块**；echo 文本不含括号字符。

### 1.3 32 位 DLL 的编译目标
**现象**：运行时 `BadImageFormatException` 或找不到 DLL。
**原因**：锁厂 DLL 是 32 位，程序必须是 x86。
**解决**：C# 编译加 `/platform:x86`（Framework 自带 csc 即可，无需安装 SDK）。

### 1.4 缺 using / 编译报 CS0246
**现象**：`List`/`Dictionary` 找不到（CS0246）。
**原因**：批量队列等功能用了 `System.Collections.Generic` 但文件头没 using。
**解决**：逐个文件核对 using；注意用正则检查时排除注释误报（如 `IsLockNoFormat` 里的 `Format` 字符、`[STAThread]` 里的 `Thread`）。

## 2. 运行时/界面层的坑

### 2.1 WinForms 跨线程访问控件异常
**现象**：后台线程操作控件抛 `InvalidOperationException`（跨线程访问）。
**解决**：**在 UI 线程预取控件值**（点按钮时先读入局部变量再传给后台线程）；UI 更新用 `BeginInvoke`。

### 2.2 串口刚打开立即读卡 → 误报"无卡"
**现象**：打开串口后同一秒点读卡，返回无卡；几秒后重试成功。
**原因**：发卡机刚上电/初始化未就绪。
**解决**：`OpenPort` 成功后 `Thread.Sleep(400)` 再操作。

### 2.3 新卡(返回码7)被误报"读卡失败"
**现象**：读到空白新卡（注销后的卡）显示"读卡失败：新卡"。
**原因**：代码把 7 归入错误分支。**7=新卡是正常状态**（卡存在但没数据）。
**解决**：
- 读卡 r==7 → 提示"这是一张新卡（空白卡），尚未写入任何房间信息"（Info 图标）。
- 注销 r==7 → 提示"该卡本来就是新卡，无需注销"。

### 2.4 DateTimePicker 难用 / 弹出后还要再点箭头
**现象**：失效时间选择控件难操作。
**解决**：用 **MaskedTextBox（掩码 `0000-00-00 00:00` + 大号字体）** 支持直接打字，右侧【📅】按钮弹出**自定义日历弹窗**（MonthCalendar 选日期 + 时/分 NumericUpDown + 确定/取消），一次操作到位。
**坑**：`DateTimePicker.DropDown` 是**事件**不是方法，`DropDown()` 调用会报 CS0079，用 `Visible+BringToFront+Focus` 代替。

### 2.5 界面被要求去掉日志框/状态栏
**注意**：PMS 认结果的 `{日期}/{UID}.txt` 记录文件**不能删不能合并**；人工日志另建统一文件（如 `开锁日志.log`，一行一条追加，`lock` 保证线程安全）。

## 3. 并发与重复开卡

### 3.1 多进程抢串口 → 单实例 Mutex + 命名管道（方案B）
**背景**：PMS 每次开卡启动新进程，重复开卡 = 多进程并发抢串口。
**方案**：
1. 首实例创建命名 `Mutex(true, MutexName)` 持有；后续实例 `Mutex.WaitOne(0)` 失败 → 说明已有实例。
2. 后续实例把参数通过**命名管道**（`NamedPipeClientStream` → `PipeServer.Send(args[0])`）转发给首实例后退出。
3. 首实例（`NamedPipeServerStream` 异步监听）收到参数 → `ApplyNewTask()`：`Show+Activate+BringToFront` + 解析新房号替换队列 + 刷新界面。
4. 进程内 `lock (SdkLock)` 串行化所有 SDK 调用。
5. 全部房间完成 → `Close()` 释放 Mutex/串口。

### 3.2 Windows 前台锁定：后台实例弹不到前台
**现象**：方案B 生效（信息已更新）但窗口只在任务栏闪图标。
**原因**：系统只允许"前台进程/刚有用户输入"的进程抢前台，后台 `Activate/BringToFront` 无效。
**解决（可选，先确认需求）**：`RestoreToForeground()` 三层保障：
1. 最小化恢复：`WindowState=Normal` + `ShowWindow(SW_RESTORE)`；
2. `AttachThreadInput(当前线程, 前台线程, true)` → `SetForegroundWindow` → 摘除；
3. 兜底：`keybd_event(VK_MENU)` 模拟 Alt 获得"用户输入"资格 → `SetForegroundWindow`。
**⚠️ 经验教训**：用户可能不接受强制抢前台（实测要求回退过），**先问再实现**。

## 4. SDK 返回码速查（汉庭 NewICdll.dll）

| 返回码 | 含义 | 处理建议 |
|---|---|---|
| 0 | 成功 | 正常流程 |
| 1 | 无卡 | 提示"未感应到卡，请放稳后重试" |
| 2 | 卡错误 | 换卡重试 |
| 3 | 密码错误 | 检查 set.ini 密钥 Pwd |
| 4 | 串口错误 | 检查串口号、发卡机电源/USB |
| 5 | 授权错误 | 检查授权文件 |
| 7 | **新卡（空白卡）** | **正常状态**，友好提示，不当失败 |
| 10 | 数据错误 | 检查卡数据格式 |
| 11 | 配置错误 | 检查 set.ini 配置 |

## 5. 房号/锁编号格式速查

| 场景 | 格式 | 示例 |
|---|---|---|
| PMS 下发房门号 | 4位数字 | `8201` |
| 锁编号（卡内 R 字段） | `R楼-层-房-门` | `R1-2-1-0` |
| 卡数据 | `T0\|R...\|DyyMMddHHmm\|OyyMMddHHmm\|L0` | `T0\|R1-2-1-0\|D2608061550\|O2608071400\|L0` |
| 时间（卡内） | `yyMMddHHmm` | `2608071400` |
| 时间（PMS 下发） | `yyyy-MM-dd HH:mm:ss` | `2026-08-07 12:00:00` |

**8xxx 房号 → 锁编号规则**：`R1-{房号第2位}-{房号后两位去前导零}-0`。例：8201→R1-2-1-0、8210→R1-2-10-0、8523→R1-5-23-0。

## 6. 需求边界与经验教训（重要）

- **不要擅自做结构性大改**：用户对"全屏独占/键盘锁定/单实例管道/日志隐藏"等未经明确要求的改动可能不满意并要求回退。**每次大改先确认，改动范围最小化**。
- **逆向"看懂"≠"改源码"**：商业编译型软件（如原 Delphi exe）只能逆向分析，无法还原成可编译源码；需要新功能时**重写对接程序**（走协议），不要试图改原 exe。
- **手动模式问题**：用户可能要求去掉"手动模式"（无参数启动直接提示退出），因为正常业务全靠 PMS 驱动；但 PMS 的**读卡/注销指令**（`room_no="读卡"` 或 `action=ReadCard/HotelCheckOut`）仍需打开操作界面，否则 PMS 对应功能失效。
- **多房间批量**：PMS 批量入住走 `Door_lock_call_initiate`，多房间数组逐个下发；对接程序用**队列**：开卡成功自动切换下一间（界面显示"第 X/N 间"），全部完成自动退出。
- **lockmodel（锁型号）**：PMS 后台配置后随指令下发，原版 exe 靠它选择同目录下对应锁厂接口目录；简化版对接程序可固定调用一个锁厂 DLL，日志显示后台 lockmodel 值便于核对。
- **界面显示房间号**：PMS 下发可能是房门号(8201)也可能是锁编号(R1-2-1-0)；显示用"锁编号反查房号"保证一致性；显示文字如"正在开：8201房间"。
